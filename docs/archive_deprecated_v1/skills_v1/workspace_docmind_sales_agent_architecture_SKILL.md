## 2. Core Design Principles (DocMind v3.1.5.3)

1. **Conflict Priority Hierarchy (Highest to Lowest):**
   ```text
   Safety (PRE-02/04 + Neurological Red Flags) > Explicit Opt-Out (PRE-03) > Emotion/Frustration Rescue (R01) > State Progression > Value Defense (1st Objection) > 1-Step Downsell (2nd Objection / Explicit Cheaper Request) > Style
   ```
2. **Veteran Sales Two-Step Price Objection (`R11`, `R11A`, `R11B`, `R12`, `R13B`):**
   - **1st Price Objection (normal, e.g., `"đắt thế"`, `"Đắt"`):** Hold `heldPackage`/`heldDuration`. Do **NOT** downsell, do **NOT** add `heldPackage`/`heldDuration` to `rejectedPackages`/`rejectedDurations`, do **NOT** repeat old numeric price. Empathize + defend quality + controlled qualitative social proof (if `docsHasFeedback == true`) + invite 1-session trial with `🥰` (`typing_delay_ms = 2000` on Bubble 2 per `VR-014A`).
   - **Explicit Downsell Request (`"Có gói nào ngắn hơn rẻ hơn không?"`, `"Có gói 30 phút thử xem sao không em?"`) or 2nd Price Objection (`"Nhưng vẫn thấy hơi đắt em ạ"`):** Downsell 1 step (`90 -> 60 -> 45 -> 30 phút`), mark prior `heldPackage`/`heldDuration` in `rejectedPackages`/`rejectedDurations`, **NEVER** mention rejected duration or old price (`VR-004A`), Bubble 2 `typing_delay_ms >= 10000`. If no lower package exists in KB, handoff (`NO_LOWER_PACKAGE_HANDOFF`, 1 bubble, 0 questions).
   - **Trial Acceptance (`"Thử xem sao"`, `"Đắt thế nhưng thôi thử xem sao"`):** If `downsellOffered == false`, confirm booking for `heldPackage` (never call it `"gói ngắn"`). If `downsellOffered == true`, confirm booking for `downsellPackage` (`"gói ngắn 30 phút"`). Never repeat price; ask branch & time slot (`typing_delay_ms = 2000`).
3. **Strong Rejection vs Soft `"thôi"` (`R13C`):**
   - Standalone `"thôi"` inside `"Đắt thế nhưng thôi thử xem sao"` is a soft transition into `TRIAL_ACCEPTANCE`, **NOT** `STRONG_REJECTION`. Only explicit rejection phrases (`"thôi khỏi"`, `"thôi không làm"`, `"không làm nữa"`, `"để lúc khác"`) trigger `STRONG_REJECTION` (`GRACEFUL_EXIT_AFTER_REJECTION`, 1 bubble, 0 questions).
4. **Controlled Social Proof & Medical Grounding (`VR-007B..H`):**
   - Only use `"nhiều anh/chị sau buổi đầu trải nghiệm có phản hồi khá tốt"` when `docsHasFeedback == true`. Never invent percentages (`90%`, `95%`), fake counts (`hàng nghìn khách`), absolute guarantees (`chắc chắn 100%`), or medical cure claims (`chữa khỏi`, `điều trị dứt điểm`). Controlled muscle-relaxation phrasing (`"ấn huyệt làm mềm cơ vùng cổ vai giúp nhẹ đầu và đỡ tê mỏi"`) is allowed for mild symptoms.
5. **Active Prompt Below 900 Characters:**
   - Always keep `persona_config.active_prompt_compact <= 900` chars (hard cap `<= 1200` chars).

## 5. Domain-Agnostic Multi-Tenant Architecture (v3.2.0 — Zero Domain Hardcoding)

1. **Zero Domain Hardcode Gate in `src/main/java/`:**
   - All tenant identity (`bot_name`, `self_pronoun`, `default_customer_pronoun`, `opening_bubbles`, `post_price_delay_ms`), domain vocabulary (`domain_keywords`, `symptom_keywords`, `body_area_keywords`, `service_family_keywords`), and catalog packages/prices are loaded dynamically from `knowledge_pages.persona_config` and Active Chunks (`documents` + `chunks` scoped by `page_id`).
   - Mandatory gate: `grep -rnwiE "(nàng sen|an nhiên|vai gáy|mỏi gối|ngâm thảo dược|ráy tai|280k|350k)" src/main/java/` MUST return **0 lines**.
2. **Multi-Entity Extraction & Inverted Vietnamese Normalization:**
   - `ConversationState.extractAllNeeds(text, domainKeywords)` and `ConversationState.extractTargetScopes(text, domainKeywords)` extract ALL customer needs and target scopes in order, normalizing inverted Vietnamese clauses (`"Tôi bị chân đau, mỏi gối tê bì"` -> `"đau chân, mỏi gối và tê bì"`, `targetScopes = ["chân", "gối"]`) and protecting compound scopes (`"chân răng"` -> `"răng"`, never `"chân"`).
3. **Scope-Grounded Recommendation (`R03`, `R04`, `R05`):**
   - `PrimaryActionRouter.selectBestSingleCatalogOption` strictly filters candidate packages against `targetScopes` (`knownBodyAreas`). Off-scope packages are excluded (`score = -1000`). If no package in Active Chunks matches `targetScopes`, the router triggers `HARD_HANDOFF_COMPLAINT` (`UNGROUNDED_SCOPE_HANDOFF`) rather than hallucinating or forcing an unrelated service.
4. **`ENTITY_MISMATCH_CORRECTION` & Anti-Keyword-Hijacking (`R00-MISMATCH-CORRECTION-RESCUE`):**
   - `SentimentIntentLayer.isEntityMismatchCorrection(text)` and `stripMismatchCritiqueClause(text)` strip critique clauses (`"mà mày đi tư vấn massage cổ là sao"`) before extracting needs/scopes, storing `"massage cổ"` as `rejectedWrongOffer` and clearing `heldPackage`/`lastQuotedPackage`. When accompanied by harsh pronouns (`"tao"`, `"mày"`) or `frustrationCount >= 1`, the router immediately emits `MISMATCH_CORRECTION_HANDOFF` (1 bubble, 0 questions, `needs_human_handoff = true`).
